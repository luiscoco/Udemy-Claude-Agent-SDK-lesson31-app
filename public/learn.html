01

Enable and detect AskUserQuestion

Keep AskUserQuestion in an explicit tools list and route that tool name to a dedicated question handler. Normal tool permission requests belong in a separate branch. An allow entry does not provide the missing human answers.

02

Present Claude’s actual questions

Parse questions, header, options and multiSelect. Claude owns the wording and choices. The host renders radio buttons or checkboxes and offers a custom Other answer without appending new SDK questions.

03

Return full-text answer keys

Preserve the original questions array. Map each full question text to its selected label, joined multi-select labels or the student’s custom answer. A header or option index is not the SDK answer key.

04

Compare custom text with a general reply

Other belongs in answers[question]. A general response dismisses the structured card and uses the optional response field instead. The UI supports both, and offline tests distinguish their returned shapes.

05

Render optional previews

TypeScript toolConfig can request HTML or Markdown previews. Display only previews the model actually supplies. The SDK rejects certain unsafe HTML; the browser also sanitizes fragments and uses a sandboxed iframe with a restrictive content policy.

06

Handle plan mode, cancellation and limits

Answer real questions before a read-only plan. Abort and timeout settle the waiting promise without inventing an answer. The UI is a local teaching sample; a long-lived production workflow may need documented deferred execution and authenticated request ownership.
