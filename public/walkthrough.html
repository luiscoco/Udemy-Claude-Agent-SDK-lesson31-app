01

Question ownership

Claude generates the questions and options. The host can add an Other control to its own UI without modifying the original questions array. Questions invented by the application belong in a separate application flow.

02

Answer shape

Use full question text as each key, not the short header. The app joins multi-select labels with comma-space, which the SDK supports. Custom Other text is a per-question answer; response is a general reply replacing the structured answer list.

03

Question and preview limits

The question tool supports one to four questions and two to four options per question. Preview fields are optional. The configured format applies to the session but does not guarantee a preview for every option.

04

HTML preview boundaries

The SDK rejects script, style elements and DOCTYPE in generated HTML previews. This UI also sanitizes allowed tags and attributes, uses a sandbox without scripts and applies a content policy that blocks external resources. Trusted wrapper CSS keeps preview text readable.

05

Plan mode

The plan experiment asks an actual clarifying question before a short read-only plan. It exposes only Read and AskUserQuestion and never enables edits. A model-generated plan artifact, if attempted by the runtime, remains outside the permitted tool scope and is logged.

06

Waiting versus deferred execution

This app keeps a process alive while the callback promise waits. A two-minute timeout cancels and settles it. The documented PreToolUse defer pattern is a separate design for resuming persisted sessions and is explained here without pretending it is implemented.

07

Local teaching scope

The loopback server accepts one active query and checks POST origins. Request IDs are single-use; invalid or stale decisions cannot approve another request. A deployed multi-user app needs authenticated ownership and its own durable lifecycle.

08

Evidence and API usage

All questions, previews and native results in the live examples come from actual SDK calls. Scripted CLI/test selections are labelled explicitly. Each query has a $0.45 SDK budget threshold, not a prepaid cap. Credentials, dependencies and all teaching media stay outside Git.

10. Resolve the answer POST once

Look up the pending request, validate the submitted selection against its original questions, then settle it once. Invalid submissions leave the same request waiting; stale IDs are rejected.

Source: src/questions.ts · lines 122–128 · selected source; surrounding code omitted

export function resolveAnswers(id: string, decision: unknown) {
  const item = pending.get(id);
  if (!item) return false;
  const result = mapAnswers(item.questions, decision);
  item.settle({ ...result, requestId: id });
  return true;
}
